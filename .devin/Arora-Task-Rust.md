### PVAULT01

Profile vault crypto module — genuine Rust task (audited crypto crates, zeroize), standalone, no deps. New `profilevault` module inside `rustcore` exposed over the existing C FFI.

**Vault format** `vault.arv` (single file, streamable):
- header: magic `ARV1` | algo_id | argon2id params (m,t,p) | salt(32B) | chunk_size | chunk_count
- HMAC-SHA-512 over header (keyed by mac_key)
- payload: tar-style pack of the profile dir, chunked (16MB); each chunk independently encrypted + tagged
- HMAC-SHA-512 over full ciphertext

**Key schedule — two-tier (wrapped vault key):** the vault key is **random**, not password-derived. At seal: generate 512-bit `vault_key` (enc_key 256b + mac_key 256b) from the OS RNG — the "AES-512-class" composite (AES is only standardized to 256-bit keys; 512-bit composite = what vendors mean). Argon2id(password, salt — default 64MB / t=3 / p=4, params in header) → 256-bit `kek`; header stores `AEAD_encrypt(kek, vault_key)`. Unseal is a **two-stage check producing distinct errors**: (1) unwrap tag fails → `WrongPassword`; (2) unwrap ok but ciphertext HMAC fails → `Tampered`. Edge honestly documented: bits flipped inside the wrapped-key field report as WrongPassword (still fails closed). Side benefit — password change only re-wraps, no re-encrypt. `zeroize` everything; password and vault_key bytes never persisted.

**No partial unpack (structural):** unseal is two-pass — pass 1 stream-verifies the full ciphertext HMAC before writing any plaintext; pass 2 decrypts into `out_dir.tmp`, fsyncs, atomic-renames on success only. Any failure = zero unpacked artifacts.

**Algorithm agility (user-requested):** `algo_id` field selects:
- `0x01` = AES-256-GCM per chunk + HMAC-SHA-512 — **default** (AES-NI, audited, boring)
- `0x02` = Threefish-1024 in XEX-style tweakable mode + Skein-MAC — optional; use RustCrypto `threefish`/`skein` crates, document in-code that these are unaudited upstream (honest caveat; the primitive is sound — designed for tweakable disk encryption)

Per-chunk nonces/tweaks = `salt_prefix || chunk_index`; **fresh salt every seal** — never reuse key+nonce across re-seals.

**FFI surface:** `rv_seal(dir, password, algo, out_path) -> rc`, `rv_unseal(blob, password, out_dir) -> rc`, `rv_verify(blob, password) -> rc` (fast header+HMAC check without unpack), `rv_inspect(blob) -> {algo, kdf params}` for UI display. Error codes honest: WrongPassword / Tampered / IoError / UnsupportedAlgo — never conflate. C++ callers must be able to stream progress (chunk callback or progress counter) for UI progress bars.

**Verify:** legs — round-trip both algos byte-identical; wrong password → WrongPassword; flipped ciphertext byte → Tampered with zero partial output; header tamper caught by header MAC; zeroize confirmed (no key material in freed buffers); make check PASS on this lane. Tests: REQUIRED — dedicated rust-side unit tests + at least one FFI-level C++ autotest leg; smoke-only does not count as done.

Outcome — landed `src/rustcore/src/profilevault.rs` (~1800 lines): the ARV1 container is a fixed 153-byte header (magic/algo/argon2id params/salt/chunk geometry + wrap_nonce/wrapped vault_key/wrap_tag) MACed by HMAC-SHA-512 under mac_key, then a streamable payload of `len | ct | tag` frames (16MiB chunks default, bounds-checked on both write and read), then the whole-payload HMAC-SHA-512 trailer. The two-tier key schedule is exactly as spec'd: `VaultKey::random()` (64B OS-RNG enc||mac) wrapped by an Argon2id KEK (defaults 64MiB/t3/p4, params stored in the header), so `rv_rewrap` changes the password in ~217 rewritten bytes without touching the payload — salt stays because chunk tweaks derive from it and mac_key is unchanged.
